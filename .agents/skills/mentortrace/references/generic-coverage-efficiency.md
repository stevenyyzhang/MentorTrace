# Generic coverage and bounded post-processing

New adaptive runs pin `coverage_basis_v1: 1`, `delivery_focus: 1` and
`canonical_draft: 2`. Old frozen protocols are unchanged. These rules supersede
older output-shape instructions only where explicitly stated below.

## Discover from this manuscript

In the existing Reader/Expert planning call, `coverage_basis` records concise,
independently answerable questions triggered by the actual manuscript. Use anchors
and existing object IDs for claims, method steps, result comparisons, citation
attributions and paragraph dependencies. Cross-object questions preserve both
endpoints. Do not turn this into all possible object pairs, every paragraph times
every dimension, or a known-answer list. Page accounting helps detect blank coverage;
it does not prove that all relevant questions were discovered.

Reader/Expert answer these questions through references to their actual checks.
`coverage_answers` distinguishes answered, partial, unknown, not_applicable and
unfinished. Partial answers retain the remaining question. A valid calculation does
not prove a broader printed claim or a cited source's contribution. Reuse evidence
and check IDs rather than restate it in another narrative. Add overlooked questions
within the same lane call. Existing case-based reading and technical checks remain.

The existing source-only review first examines the manuscript for gaps in that
basis, then checks the actual scope and evidence of the recorded answers. Its
`coverage_audit` must route narrowed, unknown and unattempted questions to anchored
issues. Verify resolves these once in `execution_resolutions`; a missing review is
not itself an author defect. This adds no separate manuscript-wide review call.

Concrete unresolved questions from technical aspects, configuration dimensions,
Reader tasks, coverage answers and explicit proposals enter candidate accounting.
Generic capability limitations do not become author requests. Distinct origins are
preserved; Merge/Verify may consolidate genuinely equivalent questions with explicit
links, not topic similarity. Unknowns receive author-confirmation routes or an
evidence-based disposition. Supported, compatible organization/style suggestions
remain optional even when comparative benefit is uncertain or not claimed.

Advisor retains its own full-manuscript, case-driven initial review. Do not send it
the Reader/Expert plan, coverage basis, findings, or historical answers. Cross-lane
work begins only after initial outputs freeze and is never relabeled independent
Advisor discovery. No manuscript-specific number, figure, missing-request ID or
historical expected answer belongs in these reusable rules or public fixtures.

## Reduce avoidable work before reducing context

1. Use one authored record per coordinated report group. Each `report_fragments`
   row owns its delivery map, actions, checks, requirement/candidate delivery,
   language realizations and attribution; `canonical_draft.py` derives the ordinary report
   and lists. Source requirement component IDs remain the canonical requirements.
   Exact local `text_units` references may supply repeated passages/excerpts; the
   program expands them literally. Each independent requirement keeps its own status.
   Cross-group `quote_group_ids` bind every excerpt to its complete group and create
   dependencies. Do not repeat the same action in multiple owning groups. Both delivery gates
   still judge whether the actual prose preserves every condition and alternative.
2. Update a group and its action/check/coverage metadata together with
   `canonical_draft.py --response ... --replacements ... --expected-sha256 ... --out ...`.
   Save a new version. Stale derived text/maps, duplicate owners and out-of-group
   quotations fail locally. Original evidence still follows the source-fidelity
   rules. Structural consistency does not prove that a changed action is correct;
   renew affected semantic checks and the final global review. The native runner
   prepares and executes this transaction automatically after an actual report defect.
   Each action records its own applicability in `action_bindings`; independent grammar
   edits do not inherit a conditional extension’s author prerequisites. Changed
   assertions carry actual source support and are checked in the existing local review.
3. For local delivery requests, `delivery_focus.py` removes unrelated registry rows
   and routing records. By default it keeps the complete manuscript, images, report,
   verified targets and execution evidence. Coverage retains complete selected A
   units and transitive duplicate references. Source-field checks retain historical
   originals; frozen-component/language-only checks do not receive unrelated history.
   Full global context is retained. More aggressive passage/page scoping requires
   the existing explicit, bound dependency assessment; lack of evidence is never
   solved by truncation. Report a precise expansion request if the local context
   proves insufficient.
4. Use a single named-record output contract. Legacy column responses remain readable
   for historical replay. Shared strings/judgments are exact references, never topic
   summaries. The runner normalizes only unambiguous transport representations while
   preserving raw responses and change provenance. Missing reasons, unsupported
   assertions, false quotations and negative semantic judgments require real repair.
5. Validate all completed local records and collect all currently known defects
   before a repair wave. Group related defects with their shared context; submit
   only invalidated tasks. Do not launch globals while locals are unresolved. Use
   the ordinary single global call when the complete actual input fits. Use the
   two complete views plus synthesis only when capacity requires it, not routinely
   in addition to a successful ordinary global review. Preflight before creating a
   frozen derived bundle. Reuse exact completed requests with actual provenance;
   a report edit is not a metadata-only repair.

For `draft_context_v1`, post-freeze drafting uses `draft_context.py` to supply
complete source records linked to assigned and explicitly dependent verified
requests. Preserve shared-requirement/transfer links, editorial alternatives,
admitted transitive Expression companions and private source episodes. All
manuscript pages, images, verified requests, coverage limits and unresolved items
remain. Initial Advisor ID-remapping administration is omitted; actual source
judgments and summaries stay. Report preamble inventory (call settings, recording
status and source/batch counts) goes only to part 1, which owns that text; this does
not remove technical coverage, unknowns or execution observations from other parts.
Unknown/incomplete lineage retains the full
writing-source input and records the fallback, without a new model call. Frozen
full inputs remain the validation authority; partial views never replace them.
This filter does not run in initial discovery or independent Advisor review.
Do not split an otherwise fitting request just to claim smaller per-call inputs.

Stop adding model work when both required gates pass. A recoverable failed wave
requires continuation, not an unfinished final handoff. Repair the concrete cause;
do not repeatedly ask an unchanged negative report for approval. Model, effort,
Standard tier, output reserves and independence requirements do not change for speed.

## Measure honestly

Track initial reviews, source review, Merge/Verify, drafting, local delivery,
global review, deterministic checks and repairs separately. Record wall time,
actual provider input/cached/output tokens, model calls and repair causes. Shared
account quota differences are rounded observations, not a per-task invoice.
