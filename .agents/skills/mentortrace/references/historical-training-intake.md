# Historical training intake

Read this reference only for an explicit request to learn conditional concerns from supplied historical feedback and manuscript versions. It does not change the autonomous diagnosis contract in advisor-evidence.md or permit target comments and future target drafts in an independent review.

## Mixed materials and authority

Inventory only the supplied collection and relevant existing source records. Preserve original bytes and hashes; save derived records privately. Deduplicate by content while retaining every alias and archive-member path. Read archives in memory or into a separate safe analysis area, never over the supplied sources. A filename, timestamp or folder number suggests a comparison but does not establish chronology, authorship or a compiled-PDF match.

Classify whole manuscripts, annotated versions, unannotated versions, figure assets, auxiliary files and inaccessible objects separately. For a PDF/EPS figure dependency, resolve an active LaTeX graphics reference in its actual source directory; a one-page PDF without annotations is only a candidate asset. Do not count its captions or axes as mentor feedback. Commented-out references are inactive. Retain unreferenced assets without assuming they are required or useless.

Use the user's latest alias decisions. Confirmed student replies, self-explanations, unknown-author marks and compiler output are context, not mentor instructions. A plausible voice or a matching later edit is not identity evidence. Where identity or chronology remains unknown, retain that uncertainty and continue work that does not depend on it. Do not introduce a human approval checkpoint when the user has already authorized autonomous completion.

## Read the feedback in its manuscript and version context

Extract literal annotation contents, author, reply linkage, page, subtype, geometry and source hash. Use extraction for navigation, then read the marked source and neighboring text in the original page image under source-fidelity.md. Include unexplained highlights, strikeouts and ink in the disposition ledger without inventing their meaning.

Before classifying short edits as merely local or unclear, read related edits around the same object, paragraph and later versions together. A replacement word, moved definition and repeated qualification may jointly express a substantive requirement. Record the supporting links, existing explanation, inferred relationship and uncertainty; a document-wide fallback label is not a semantic review. Retain surface edits as such when context supports that reading, and leave genuinely unexplained marks unresolved. Accounting coverage is not recall evidence.

Do not label every empty-content annotation as paired with a rewrite. Verify the actual reply/object link, or record a separately supported contextual relationship and its limits. An absent reply link does not make the mark useless; a present link supplies context but does not by itself establish a new concern or mentor acceptance.

For LaTeX, read source, macro definitions and direct dependencies first. Compare meaningful objects and roles as well as added/deleted lines: truth versus estimate, primitive versus decision-induced statistics, assumptions, objectives, constraints, information flow and numerical generation. Preserve a byte-bound line-range packet for each decisive before/after passage. Compilation is optional when the question can be answered from source and an existing original PDF; use it to resolve a rendering ambiguity only when the necessary project files are available. A newly compiled PDF shows the source's appearance, not who changed it or whether a historical annotated PDF came from it.

Declare the diff counting unit and reading coverage. A complete line-change inventory, a short role preview and a complete semantic reading are different checks. Identical literal edits across backups may share a navigation packet, but retain each source/context and do not count them as independent feedback or assume semantic equivalence.

Keep branch, conflict-copy, backup and archive variants. Link a local source response to a feedback event only when the affected object and requirement correspond. A local match is weaker than a whole-document version mapping. Record the observed change, remaining gaps and conflicting later feedback. Do not carry an earlier mentor suggestion as a settled rule when the same history corrects it later. Different versions of one paper are dependent evidence; a short and extended paper may also share a research lineage.

## Conditional extraction and admission

Apply the existing six decision fields together: core question, new-manuscript check, relationship, historically insufficient response, potentially sufficient response and applicability boundary. Separate explicit feedback, observed manuscript state, student response and analyst transfer/sufficiency suggestions. If an explanation already exists, acknowledge it and ask whether its meaning, placement or support needs improvement. A later new request is not a failed earlier student response.

Do not turn a tentative question, contextual example, rhetorical counterexample, proposed parameter or formula edit into a mathematical fact. Hold an unsupported literal rule while preserving any defensible underlying question privately. A changed draft, local acknowledgment, silence, publication or abandonment does not prove advisor acceptance or scientific correctness.

Compare relevant existing cards in all six fields, including boundaries; keyword or title matches only retrieve candidates. Reuse the same requirement with new private version evidence. Merge only the same answerable relationship, retaining distinct requirements and conditions. Record every candidate as reuse, new, merged or held with a reason. Do not claim an independent audit or full-library semantic comparison when only a relevant subset was read, and do not impose a concern-count quota.

Check long feedback for multiple independently answerable requirements before mapping it to one card. When reviewing a suspected omission, inspect both excluded feedback and earlier reuse/merge decisions: broad thematic coverage can hide a lost condition or relationship. Preserve version evidence even when it adds no new card, and distinguish later repetition from demonstrated failure to implement an earlier request.

Admitted public cards contain English analytical abstractions and opaque source links, without original comments, excerpts, filenames, identities or private version histories. Keep feedback-to-version and public-to-private mappings in the private analysis package. Mark training exposure and require the importer's matching promotion registry. Preserve old frozen snapshots; create the new archive, complete-field runtime batches, manifest and FREEZE together. Check unique/order-preserving coverage, original-card equality, source hashes, aliases, private-source exclusion and runtime batch capacity locally. Contract and integrity checks do not establish diagnostic improvement; evaluation needs an independently justified held-out family and controlled inputs/settings.
