# Compact delivery v2

New adaptive runs pin `delivery_compact: 1` in addition to hardening. This version
changes delivery transport and closure, not Advisor discovery, scientific standards,
required coverage, model/effort/tier or capacity reserves. Frozen v1 requests stay v1.

## One packet-specific contract

`delivery_protocol.py` is the v2 output-column and prompt authority. The request
preparer selects only the actual packet's kinds and applicable checks. It replaces
legacy delivery/schema/fidelity/concision instruction stacking; it does not append
another rule block. Target packets retain factual evidence and conditional/reuse rules;
language packets retain complete relevant source operations and extent checks; global
packets retain the whole report, inventories, Original checks and applicable clarity,
economy/history checks. Global receives actual local completion and language records.

Explicit dependency scoping still requires its complete assessment. Without one, keep
full semantic context. Only program routing paths, rule hashes, duplicate unassigned
Expression declarations and module documentation are removed from model payloads.
Complete source/report text, conditions and evidence are not clipped to fit capacity.

## Smaller output, same judgments

Model output is `{protocol:"mentortrace_delivery_v2",answers:[[answer_slot,record]],limits:[]}`.
The request gives each task its numeric answer_slot. New requests use named `{value:{...}}` records only. Legacy column-order responses
with explicit `$omit:true` remain decodable for saved-output replay. A short slot prevents
an omitted row from shifting later judgments onto different tasks. Unknown, missing
and failed semantic judgments retain their actual status. No program fills a missing
reason or pass. Named `{value:{...}}` records preserve extensions; named shared judgments
retain the existing explicit same-judgment rule. Evidence and conditional details stay
literal. Exact shared references reduce repeated text; named records avoid column/schema confusion.
The number of required semantic checks is unchanged.

New adaptive runs pin `normal_flow_v1: 1`. Long repeated literal task strings may
use `$literal:[answer_slot,path]` (Source uses its assigned task ID); paths address
actual task data and must resolve to a complete string. Existing `texts/$text`
shares identical complete strings. These are exact output references, not shorter
paraphrases, inferred evidence or default judgments. Both collectors and final
validators see expanded records; raw responses and reference provenance remain.

The runner supplies reviewer identity/context and transport hashes from the actual
completed fresh execution audit. Actual declared model limits remain in the record.
Unexpected model-generated execution metadata is retained as ignored metadata alongside
the immutable raw output, never trusted as identity. The collector re-expands raw v2
output against the same slot/column map and verifies its audit; it cannot relabel a
changed model output as an equivalent response.

## Bounded native closure

`run_review_packet.py --bundle ... --calls ...` uses the closure automatically for v2
bundles (without --packet). The existing three-worker local wave runs first. Known
completed, independently assignable invalid/missing local records are checkpointed
and revalidated. `delivery_cycle.py` builds the ordinary delta ledger and a new native
bundle containing only pending corrections plus a global task. All known defects
and actual prior values are supplied together only to affected local tasks.

There is at most one correction wave. This is a new correction request with its own
provenance, never a relabeled old response. Unchanged valid source fields, target
judgments, language groups and native-valid B rows retain their exact actual values
and provenance. Newly assigned failed tasks have no inherited template verdict.
Optional missing B outcomes may retain that outcome on an exactly identical report;
they never become a claim that an action was delivered.

New adaptive runs also pin `native_report_repair: 1`. After locals pass, the
actual global review and BOTH native delivery gates must pass. A semantic report
failure now enters `native_delivery.py` and `report_revision.py` automatically:
collect actual negative judgments, prepare one source-bound group transaction,
apply all seven owned views together, derive affected groups and their dependencies,
then prepare the ordinary delta and recheck pending tasks plus the global. The full
report/manuscript and relevant complete source evidence remain available. Positive
unchanged local judgments are not copied into the repair prompt as extra prose.

The same authorization, model, effort and tier apply. Each reviewer cycle allows
one record-correction wave; a native closure permits at most two report transactions,
each with at most one correction of its saved malformed/invalid transaction output.
No-progress fingerprints and immutable bindings prevent repeated approval requests.
These are bounded recovery limits, not a permission to call unfinished work delivered.
At the limit, retain an explicit resumable continuation and identify the concrete
remaining blocker; do not launch more initial lanes. Missing author facts remain
specific conditional actions, not invented facts or an automatic rejection of a report.

All revisions save new files. OS locks release after a crash; saved successful calls
are hash/settings-checked and reused. An uncertain submission is reconciled from saved
status before any retry. Completed resumes revalidate raw provenance and both gates.
Old frozen protocols retain their original record-only path. Automatic manuscript
application remains outside this report-repair workflow.

Global receives every actual local judgment body and its evidence/provenance, in
addition to completion indexes. Hashes never substitute for those judgments. Large
payloads may use exact reversible schema/string interning; preserve the full decoded
data and capacity reserves. Explicit transport-only rule migrations may reuse locally
valid old judgments with matching old/new rule hashes; changing scientific validators
invalidates reuse. Appended historical sources leave their new units pending and do
not by themselves invalidate unchanged prior source units.

Successful resumes verify actual raw/audit provenance and both final gates with zero
new submissions. Interrupted corrections reuse their frozen plan and completed outputs.
An offline caller may use `python scripts/delivery_cycle.py --bundle ... --responses ...
--out ...` to prepare corrections without invoking a model. Previewing recoverable
delivery on an old frozen audit does not enable/rewrite its initial discovery protocol.

## Verification and limits

Under `normal_flow_v1`, global reuse requires a previously accepted report, identical
report and source/evidence bindings, unchanged review-rule hashes and actual model,
effort and tier, complete local/B carryover, and no affected or invalid records.
The runner revalidates those predicates and preserves the actual global provenance;
both final gates still run. A formatting change does not alone require a new review,
but missing, negative or semantically changed judgments never qualify. Old protocols
and uncertain dependency scopes retain their conservative behavior.

Apply final-validator excerpt and local-notice rules at initial response collection.
Malformed shared evidence invalidates its actual users, not every task in the packet.
Local checks omit unrelated completed peer reviews; global checks retain them.
Require historical completeness only when actual history is explicitly bound.

Report rewriting receives actual semantic or language failures, not reviewer-record
format defects. Project writing candidates to the affected groups and their admitted
dependencies; retain full manuscript, report prose, frozen requirements and final
opinions. Read-only groups omit repeated bookkeeping in the model view only; full
saved records remain validation authority. Unknown scope falls back to full input.
An explicit `instruction_only_group_ids` declaration narrows incremental review only
when every other prose field and owned delivery record is mechanically unchanged.
Explicit semantic dependencies, changed local checks and a fresh global judgment
remain mandatory for edited reports. With `normal_flow_v1`, the existing revision
call may supply complete `scope_units`: actual changed requirements, claim/condition
assessment and every shared-opinion peer reviewed. Shared opinion IDs alone then do
not invalidate peers. Changed shared requirements and explicit/quotation dependencies
still propagate; missing/uncertain scope falls back to conservative expansion. Changed
group locals and the full cross-context global review are never waived.

If complete global input exceeds capacity, do not terminate the authorized task or
delete leaf judgments. The native runner routes a proven capacity overflow through `scripts/delivery_global_views.py`: prepare and
finish pending locals, then assign every actual source/coverage body to a complete
source-preservation global view and every actual target/language body to a complete
facts/language global view. Both receive the full report and relevant complete
evidence; preflight every view before submission. The assigned-ID union must cover
all actual local records. A fresh synthesis model inspects both actual global
results, the full report and inventories for cross-view conflicts and supplies
the ordinary final global record. Python never invents that acceptance. Any real
scoped defect requires correction before synthesis. Record this compositional
review honestly; the synthesis did not independently reread every leaf body.
With `normal_flow_v1`, synthesis owns cross-view conflicts and unresolved interfaces.
It receives the full report, manuscript, source/target inventories, final opinions and
complete actual specialist conclusions. Full frozen-A and Expression leaf reviews
stay with their specialist views and frozen runtime context. Synthesis explicitly
adopts unchanged specialist fields via `$view:[role,field_or_path]`, retaining exact
records and file hashes, and supplies its own cross-view reasons/issues. It does not
repeat Original/Expression/clause judgments; disagreement remains a blocking issue.
Only fields actually supplied by a passing, unchanged specialist can be adopted.
The ordinary source-preservation and final-text gates still both have to pass.
