# Delivery evidence and dependency contract

This is the operational contract for new adaptive runs with `delivery_hardening: 1`.
Frozen older runs keep their original flags and raw outputs. No saved judgment is
relabeled as a new model review. This protocol changes Reader/Expert planning,
Merge/Verify retention and delivery execution; it does not constrain independent Advisor.
Use the already authorized model, effort and Standard tier. Keep three-worker maximum,
capacity reserves, source-only review isolation and both native delivery validators.

## Coverage and retention

Reader applies the selected cases to actual manuscript argument, section roles,
transitions and paragraph jobs as well as local text. Expert's object/configuration
plan names independently answerable dimensions with scope and evidence. One sufficient
aspect cannot close another unknown aspect. Dimensions are general checks generated
from this manuscript; do not embed a previous paper's answer list or require findings
per check. The system still cannot guarantee recall of ungenerated checks.

Merge retains each independently actionable requirement and each conditional branch,
without collapsing distinct conditions. Record the exact source component
and final-ID route. Verify adjudicates every proposal withdrawn by any stage, and independently
checks the proposals that Merge retained. A claim that a paragraph already exists requires frozen line and
column references plus a layout observation. Neutral extracted coordinates establish
geometry, not paragraph semantics or visual truth. Missing layout evidence leaves the
claim unresolved rather than inventing an indent. Original page images govern glyphs.

Uncertain net improvement does not justify deleting a source-supported optional
organization or mentor-style suggestion. Alternatives may remain optional, with a
specific target, operation and source. Do not promise improvement from style imitation.

## Draft once, assemble once

All confirmed findings, organization suggestions and registered optional/author-confirmation
candidates are assigned exactly once. A candidate is not merely listed in input metadata.
Each required/optional/unknown source component has an owning part, complete related
context and a `requirement_delivery` entry with literal report excerpts and a specific
condition check. Required actions cannot become optional; unknowns remain visible questions.

Return complete coordinated bilingual groups in `report_fragments`, each with a stable
`group_id`, `section` (`content|organization|language`), full `text`, verified/candidate IDs.
Only part 1 returns `report_preamble`; fragments do not contain level-2 category headings.
The assembler emits one heading per category. Shared replacement prose has one owning
group; other groups retain concrete actions or links. Preserve each complete Original
as literal manuscript text, never an analyst summary. Check formula transcriptions against
frozen source evidence. Patch only the intended generated text, never global formula substitutions.

## One canonical delivery contract

For `delivery_compact: 1`, `delivery_protocol.py` supplies the packet-specific
prompt contract; `review_contract.py` validates the expanded canonical records.
Older frozen protocols retain their original request contract.
All assertion judgments have reason and explicit domain: manuscript science requires
manuscript/direct_derivation evidence; execution facts require execution_record; report
correspondence requires report_structure. Documentary evidence binds an actual prepared
source path and hash or the supplied `evidence_source_refs` ID. It cannot prove science.

Allowed normalization is limited to recorded representation changes: joining actual
string limits, hoisting an existing reuse reason, expanding a frozen documentary source ID.
Raw responses remain byte-for-byte. No program invents statuses, judgments or passes.
All local defects are reported together. A malformed result remains saved for bounded repair.
The provider is prompted with the contract; Python validates it, rather than relying on
provider-side structured-output enforcement.

## Native local-to-global barrier

`run_review_packet.py --bundle ...` checks frozen inputs/settings/capacity before work.
It executes local packets (at most three concurrently) and inspects every actual
response. Unresolved local defects block global submission, not the authorized
correction workflow in delivery-compact.md. After local closure it derives a
hash-bound `global-ready` bundle
containing actual completion IDs/hashes/provenance, full language judgments and the
selected full Expression features. The existing global report, source and Original tasks
remain. Completion metadata is not scientific evidence or an automatic semantic pass.
For compact delivery, if the complete global request exceeds capacity, use the
complete views and fresh synthesis in delivery-compact.md. An indivisible view
that still cannot fit remains an explicit capacity obstacle; never truncate or
change reserves. Older protocols do not silently acquire this new execution path.
Use the receipt's `bundle` and `responses` for ordinary `assemble_delivery`, not the
original bundle when a derived global bundle exists. Both native gates still run.

On interruption, inspect saved raw outputs, audits and receipt before any retry. Identical
valid requests reuse actual outputs. Inspect the defect and use the native bounded
correction workflow; never blindly resubmit the same failed request or invent an
ad-hoc alternate prompt. The trace directory separates provider intervals from deterministic
validation spans; wall-time complements are not labeled as CPU work or uniquely attributed causes.

## Bounded repair and partial reuse

`python scripts/delivery_runtime.py repair --help` creates a new canonical request bundle
for actually invalid/missing local tasks. The ordinary checkpoint/delta prepare-delivery flow schedules the dependent global task after repaired locals. Provide actual
responses and, when available, the hash-bound scope assessment. It never submits a model
request. Preserve old and repaired outputs separately, then follow delta/collect and the
native gates using the actual new provenance. Do not manually clear all language groups.

`prepare_delivery_delta.py` accepts assessment `language_response:{path,sha256}` for the
actual corrected proposal metadata, `previous_phase_b:{path,sha256}` for valid previous B
rows, and `semantic_dependencies` with complete reviewer/reason and affected groups,
contexts and source/component IDs. Mechanical dependency closure supplements this actual
semantic assessment; it does not replace it. Insufficient dependency evidence falls back
to fresh review. Action-only groups use their delivery-map passages, not prose-only fallback.
An unchanged group can reuse its actual positive group judgment even if another group
failed; changed meaning, feature declaration, evidence, cross-context or rules invalidate reuse.

Only B rows whose frozen adjudication, source-specific ID routes, actual quotes and safe
contexts still bind may carry over. Unknowns and exclusions needing a new judgment remain
fresh. Global completeness and final gates are never carried over as a whole-report pass.
Invocation-scoped file reads/hashes and prepared target inventories reduce repeated local
work. A file mutation during validation fails; a later invocation reads it afresh.
Checkpoint provenance is stored once in an index, with task references to the actual origin.

## Language and Expression

Write comments as a concrete diagnosis, consequence and action. Preserve necessary
conditions, scope and alternatives; delete private drafting explanations and generic
reassurance that adds no author action. Heuristic meta candidates require explicit semantic
dispositions in the existing global review; never auto-delete a scientifically meaningful caveat.
Original and Location fields are excluded from this heuristic scan.

Expression style alignment may be the sole goal. Claim partial realization only with an
actual source operation excerpt, the adopted operation and an adapted target. Verification
checks that stated extent; full realization cannot be asserted for a partial operation.
Unselected/nonapplicable features have separate nonuse accounting, not failed realization.

## Historical comparison after independent freeze

Freeze the independent report before exposing historical material. Explicitly distinguish
workflow instructions, a still-present optional action with a changed priority, newly
ungenerated requirements and requirements actually lost along the pipeline. Never count
a workflow instruction as a manuscript defect.

`python scripts/delivery_runtime.py history-bind --help` binds the independently frozen
report, actual previous source, requirement catalog and per-ID dispositions. Its generated
historical-obligations source must be included in the ordinary preservation ledger. This
is assisted recovery, not independent discovery. Unresolved required recoveries block a
replacement claim; final `history_change_review` must inspect changed text and dependencies
with explicit reason, completed status and no remaining issues. Binding alone grants no pass.

`patch --help` uses path, old field SHA-256, exact old text and occurrence count; rejects
source-field or Original changes and malformed repeated math commands. It creates a new
output and never silently edits saved raw results. Every applied patch still requires
appropriate native delta review. Do not add model phases after required acceptance passes.

For `delivery_compact: 1`, [compact delivery](delivery-compact.md) replaces the stacked v1 prompts and standalone repair handoff with the v2 native closure. Other hardening invariants remain.
